# AES Studio

[Рабочий проект](https://netkeep80.github.io/aes/) · [Демопроект с проводкой](https://netkeep80.github.io/aes/?project=demo)

Номер выпуска виден в шапке. Нажмите **AES Studio 2.2.0**, чтобы проверить версию редактора, формат и число проводов открытого проекта. Демо сохраняет свои изменения отдельно от рабочего черновика. В автономном HTML тот же переключатель показывает версию встроенного редактора.

В режиме **Проводка** выберите жилу и нажмите цвет в инспекторе. Потяните участок линии мышью для изменения формы. Клеммы остаются привязаны к аппаратам. Кнопка **Автопрокладка** возвращает автоматический маршрут в выбранном щите.

### План объектов и сеть связей

[План демопроекта](https://netkeep80.github.io/aes/?project=demo#plan) · [Свободная сеть демопроекта](https://netkeep80.github.io/aes/?project=demo#network-free)

На плане группа получает цвет автоматически. Нажмите линию, чтобы выбрать цвет группы или вернуть автоцвет. Горизонтальный сегмент перемещается по вертикали, вертикальный — по горизонтали. При сдвиге крайнего сегмента редактор сохраняет привязку к узлу и добавляет изгиб. Автопрокладка учитывает прямоугольники всех видимых узлов.

В разделе **Сеть связей** режим **По группам** собирает устройства в колонки. В режиме **Свободная сеть** можно двигать аппараты, протягивать провода между клеммами и изменять сегменты отдельной жилы. Для выбора наложившихся жил служит таблица под схемой. Цвет жилы общий для сети, щита и ведомости. Свободные координаты устройства хранятся в `node.freeXY`, стили и ручные трассы — в необязательном массиве `diagramRoutes` с полями `view`, `key`, `color` и `points`. Координаты монтажных реек и ручные трассы в щитах хранятся отдельно.

## 1. Требования к рабочему месту

Исходный сценарий начинается с осмотра щита. По клемме аппарата нужно найти конкретный провод, его цвет и маркировку на другом конце. На выходе из шкафа тот же провод входит в кабель или идёт отдельно. Владельцу дома при обзоре участка достаточно видеть количество кабелей между зданиями. Для обслуживания требуется раскрыть эту группу и дойти до конкретной жилы и порта.

| Задача | Какие данные нужны | Приёмочная проверка |
| --- | --- | --- |
| Проследить провод внутри шкафа | Два порта, обозначения клемм, назначение и цвет жилы | Один и тот же провод виден на рейке, в сети и в журнале |
| Спроектировать укладку | Размер щита, позиции модулей, автоматические коридоры и ручные точки изгиба | Концы следуют за аппаратом, ручные точки остаются в системе координат щита |
| Найти выход «в гараж» | Идентичность щита или помещения назначения, принадлежность зданиям | Все отводы этого направления выходят снизу в одной подписанной группе |
| Выяснить, что проложено между объектами | Стабильные ID кабелей, номера жил, принадлежность узлов | Трёхжильный кабель считается одним кабелем. Его жилы раскрываются отдельно |
| Подготовить закупку | Марка, материал, сечение, число жил, длина трассы в одну сторону | Метраж кабеля учитывается один раз. Отдельные провода учитываются поштучно. Неизвестные длины показываются счётчиком |
| Оценить ток и выбрать пару сечение / номинал | Режим источника или нагрузки, напряжение, мощность, cos φ, группа одновременности, метод прокладки и длина | Видны исходные данные, ток, Iz, предложенное сечение, номинал и падение напряжения |
| Работать с существующими проектами | Прежние ID устройств, портов, щитов и связей | Черновик AES/2 открывается с прежними ID и маршрутами |

### Особенности установки AES

В проекте AES есть сразу три масштаба. На уровне аппарата важно, сколько мест он займёт и останется ли непрерывный участок для следующего модуля. На уровне щита важно, какие группы в него входят и куда уходит каждая линия. На уровне дома нужно проследить путь между распределёнными устройствами, включая оборудование за пределами корпусов. Для каждого масштаба нужна своя проекция общих данных.

| Наблюдение по материалам AES | Требование к редактору | Как проверить |
|---|---|---|
| РЭС и генератор приходят на разные входы одного АВР | Линия заканчивается на именованном порте. У аппарата может быть несколько входов одного типа | У АВР отдельно выбираются A и B |
| ИБП участвует в сетях AC и DC, реле управляет контактором | Тип принадлежит порту. Один аппарат может объединять несколько функциональных цепей | Контакт реле соединяется с управляющим входом. DC-порт нельзя соединить прямо с входом AC |
| Батареи находятся под шкафом, контроллеры планировалось перенести на другой этаж | Идентичность оборудования, место в доме и координаты на рейке хранятся отдельно | При переносе на другую рейку, в другой щит или за его пределы ID и концы линий сохраняются |
| Один многомодульный аппарат занимает несколько соседних мест | Положение задаётся щитом, рядом, начальным местом и шириной. Сумма свободных мест сама по себе не гарантирует посадку | Наложение и выход за торец отклоняются. Уменьшение корпуса проверяет все аппараты |
| В доме есть оборудование разных производителей и неизвестных типов | Нужны пользовательское название и маркировка, примечание и собственный набор портов | Для пользовательского устройства задаются стабильные ID портов, подписи, среда и направление |
| Документы станции фиксируют проектные решения, фактические места известны лишь частично | Демонстрационную раскладку можно заменить пустым проектом и заполнить по обследованию | «Проект» → «Новый проект» открывает пустую модель |
| Файлом будут пользоваться локально и на другом компьютере | Открытый формат для обмена плюс автономный снимок с самим редактором | Сохранить HTML, отключить сеть, открыть файл, изменить модель и снова экспортировать JSON |

Основание анализа — [описание установки](../README.md), [контекст размещения](../04_контекст_солнечной_станции.md) и [тарифная автоматика](../05_автоматика_тарифного_режима.md). Демонстрационный проект заимствует характерные узлы станции. Размеры корпусов, позиции, маркировки и состав бытовых групп заданы как пример.

## 2. Архитектура и дизайн рабочего места

**План объектов.** Виды «Щиты и помещения» и «Здания» сворачивают общий граф по назначению концов. Внутренние линии одного объекта скрываются на этом масштабе. Толщина связи отражает число функциональных соединений. Подпись показывает число уникальных кабелей, отдельных проводов и связей без описания. Клик раскрывает их состав. Перетаскивание узла меняет координаты только на плане.

**Проводка щита.** Это основной режим. Клеммы показаны на корпусах по их реальным позициям в модели DIN. Потяните от клеммы к клемме или выберите их двумя щелчками. В карточке нового провода можно уточнить оба обозначения, цвет, функцию, кабель и номер жилы. Межщитовую связь удобно протянуть в «Сети дома». Направления выхода появляются в обоих затронутых щитах. Кнопка подсветки выделяет провода выбранного аппарата, а масштаб 1:1 оставляет широкие щиты читаемыми с горизонтальной прокруткой. Нажатие на провод открывает ручную прокладку. Щелчки добавляют точки, перетаскивание двигает изгиб, «Сохранить трассу» фиксирует одно отменяемое изменение. «Автопрокладка» возвращает маршрут по коридорам. Чертёж отражает логические порты и введённые клеммные обозначения. Размеры конкретных клемм и длина физического кабеля вводятся отдельно.

**Перестановка аппаратов.** Слева выбирается щит, в центре показаны пронумерованные места DIN-реек, справа открыты свойства выбранного аппарата. На свободное место можно нажать. Аппарат переносится мышью в свободное место на рейке или точно задаётся числом в свойствах. Межщитовой перенос доступен в том же окне. Под рейками расположена текстовая ведомость выбранного щита.

**Сеть связей.** Колонки группируют оборудование по физическому размещению, стрелки соединяют именованные порты. Фильтр по щиту сохраняет непосредственных внешних соседей. Фильтр по среде выделяет цепи AC, DC или управления. Выбор аппарата выделяет его связи. Команда «Пути от устройства» выполняет ориентированный обход показанного графа. Таблица под схемой показывает концы линий и позволяет править соединение или его кабельную метку.

**Ведомость.** Единый перечень содержит как аппараты на рейках, так и внешние устройства с местом установки. Нажатие на строку открывает редактирование. Для нестандартного оборудования выбирается «Пользовательское устройство». Поле «ID порта» используется в ссылках, поле названия можно менять независимо.

Один шаг редактирования обновляет все представления. Удаление устройства явно перечисляет количество затронутых связей. Удаление корпуса освобождает аппараты и сохраняет их соединения. Доступны отмена и повтор последних действий в текущем сеансе.

## 3. Реализация и контракт модели AES/2

| Объект | Данные | Инвариант |
|---|---|---|
| Проект | `format`, `title`, `boards[]`, `nodes[]`, `links[]` | Объект проходит проверку целиком до замены рабочего состояния |
| Щит | ID, обозначение, название, место, число рядов и мест в ряду | Рейки и места нумеруются с 1 |
| Устройство | ID, тип, обозначение, название, маркировка, примечание, ширина, необязательное место в доме | ID сохраняется при переименовании и перемещении |
| Размещение | `place: {board, row, slot}` или `null` | Каждое занятое место принадлежит ровно одному устройству |
| Порт | Стабильный ключ, отображаемая подпись, среда и направление | Каталожный тип задаёт порты. Для `custom` они хранятся в объекте `ports` устройства |
| Линия | ID, `from: {node, port}`, `to: {node, port}`, метка | Существующие порты двух разных устройств, совместимые направления, одна среда, уникальная упорядоченная пара концов |

Здания и помещения хранятся в `areas`, принадлежность щита или внешнего аппарата задаётся ссылкой `area`. Коллекция `cables` описывает закупочные позиции. Каждая связь хранит список физических проводов `wires`. Провод содержит цвет, роль, клеммные метки и ручные точки `routes[boardId]`. Для кабельной жилы пара «ID кабеля, номер жилы» уникальна во всём проекте. Отдельный провод хранит собственные характеристики. Одному и тому же межщитовому проводу можно задать разные маршруты в двух шкафах.

Автоматическая трасса вычисляется при отрисовке из координат клемм, межрядных каналов и нижних выходов. Цвет и текстовая метка доступны независимо. Карта строит агрегаты из этих же данных и сохраняет только координаты объектов. Длины вводятся в метрах: движение карточки на плане не изменяет ведомость.

Циклы, ветвление и несколько входящих связей допустимы для описания топологии. Для двунаправленного порта стрелка фиксирует выбранное направление обхода. Обход описывает достижимость по заданным стрелкам, включая внутренние переходы на уровне узла. Положение контактов, ток КЗ, время отключения и селективность требуют отдельных исходных данных. Предварительный подбор по длительной нагрузке описан ниже.

### Расчётный профиль

Для источника используется его номинальная электрическая выходная мощность. Для нагрузки вводится активная потребляемая мощность. DC использует `I = P/U`, однофазная сеть — `I = P/(U·cosφ)`, симметричная трёхфазная — `I = P/(√3·Uл·cosφ)`. Пользователь задаёт состав питаемой группы для конкретного режима. Для нескольких индуктивных нагрузок одного напряжения складываются активные и реактивные составляющие токов. Прямое суммирование генератора и нагрузки или объединение разных напряжений отклоняется.

Для меди с изоляцией ПВХ используются таблицы B.52.2 и B.52.4, предел температуры жилы 70 °C и базовая температура воздуха 30 °C. Метод B1 применяется к отдельным проводникам в трубе, B2 — к многожильному кабелю в трубе. Рабочий диапазон сечений 1,5–120 мм². Пользователь задаёт совокупный понижающий коэффициент монтажа и доступный бюджет падения напряжения **на этом участке**. Ввод длины означает расстояние в одну сторону при равных прямом и обратном проводниках. Для оценки ΔU приняты R = 23,7/S Ом/км и X = 0,08 Ом/км в AC. Для DC реактивная составляющая равна нулю.

Из заданного ряда выбирается первый номинал In ≥ Ib, затем минимальное сечение, которое удовлетворяет одновременно In ≤ Iz после поправок и заданному ограничению ΔU. Расчёт сравнивает установленное сечение с этим номиналом, оставляя фактические данные проекта под контролем пользователя. Для другого типа изоляции, материала или способа монтажа нужна соответствующая таблица. Аппарат выбирается окончательно с учётом AC/DC, напряжения, отключающей способности, времени срабатывания, пуска и паспортных ограничений. Модель предполагает одну цепь на рассчитываемый кабель, равномерную трёхфазную нагрузку при выборе AC3 и синусоидальный ток AC; вопрос гармоник нейтрали и выбор PE требуют отдельного расчёта.

Источники — [таблицы токовой нагрузки, Energy Commission, приложения III и V](https://www.st.gov.my/ms/contents/files/download/101/Garis%20Panduan%20Pendawaian%20Elektrik%20Pepasangan%20Domestik.pdf), [формулы падения напряжения](https://www.electrical-installation.org/enwiki/Calculation_of_voltage_drop_in_steady_load_conditions), [условия выбора защиты](https://www.electrical-installation.org/enwiki/Practical_values_for_a_protective_scheme).

### Устройство и хранение

- `model.js` определяет доменную схему, каталог портов, проверку проекта, поиск свободного интервала и демонстрационные данные.
- `editor.js` реализует команды и базовые представления, обмен файлами и историю отмены. Изменение применяется к копии проекта и становится видимым только после полной проверки.
- `shell.html` и `design.css` отвечают за рабочее окно и визуальные обозначения. Сборка встраивает стили, логику и ядро хранения в один HTML. Для запуска отсутствуют внешние запросы за шрифтами и скриптами.
- На Pages рабочая копия сохраняется в `localStorage` браузера при каждом изменении. Перед очередной записью редактор сравнивает черновик с последним прочитанным значением. При обнаруженном расхождении или переполнении хранилища остаётся доступен экспорт текущей модели.
- Экспорт JSON создаёт читаемый проект `AES/2`. Для черновика старого формата предусмотрена выгрузка исходного JSON через выбор студии. При импорте проверяются версия, типы, ID, концы линий, расположение и размеры. Ошибка сохраняет текущую модель.
- Переносимый HTML содержит ядро [HTML_DBMS/4](https://github.com/netkeep80/html_dbms/tree/2d77f39c0676d3fecf2e2920f6feb9c3c9370536), DOM-элемент `#db-store`, одну опубликованную БД `AES` и JSON-модель в `chain.state.entry`. При открытии ядро читает и проверяет цепочку. Внешние программы из данных модели не исполняются. Каждая выгрузка создаёт отдельный снимок текущей модели, без истории других проектов. При работе с диска изменения живут в памяти до сохранения новой копии.
- `vendor/html_dbms-core.js` скопирован из `src/core.js` указанного коммита, Git blob `309f376e35a31c64b5caa558babda4810348de8c`. Лицензия находится рядом. Сборщик изолирует код ядра и подключает только используемые операции.

## 4. Сборка и проверка

К браузерной приёмке относятся прямое протягивание проводов в двух представлениях, ручные точки и автоматическая трасса, перемещение на плане, состав групп кабелей, ведомость и расчёт. Контрольные примеры проверяют ток AC1/AC3/DC, влияние длины и коэффициента, отклонение несовместимых расчётных групп и занятых жил, миграцию и сохранение ID.

Из корня репозитория

```sh
python3 designer/build.py
python3 -m http.server --directory dist 8000
```

GitHub Actions собирает `dist/index.html`, запускает браузерную проверку и публикует содержимое `dist` на Pages. Для локального повтора теста нужны Python с пакетом Playwright и Chrome или Chromium. Путь к браузеру можно передать в переменной `AES_CHROME`.

```sh
python3 designer/smoke.py
```
